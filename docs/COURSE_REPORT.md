# 《基于 OpenGL 的煤矿井下综采工作面虚拟仿真系统》课程报告

## 摘要

本项目使用 C++17、OpenGL 3.3 Core、GLFW、GLAD、GLM、Dear ImGui 和 CMake，实现一个可交互的煤矿井下综采工作面教学可视化。系统程序化组合 30 台液压支架、双滚筒采煤机、刮板输送机、巷道、煤壁、通风和照明设施，通过集中状态机表现初始化、联锁启动、双向割煤、端部换向、跟机移架、运煤、暂停、故障与急停。项目同时用无图形上下文逻辑测试验证安全与联动规则，并记录大语言模型生成、构建、运行和修复过程。

## 1. 背景与需求

综采工作面同时包含空间结构、重复机械、连续运动、离散状态和安全联锁，适合作为计算机图形学综合项目。课程目标不是制造工业控制器，而是用现代 OpenGL 展示几何建模、变换、着色、交互和软件架构。

核心需求分为：可辨认三维场景；采煤机、支架、输送机行为；集中状态机；五类故障；自由/固定相机、拾取；完整 ImGui；自动测试和解释文档。技术上禁止固定功能管线和单文件大程序。

## 2. 系统架构

系统分为窗口生命周期、图形资源、场景渲染、设备对象、仿真控制、粒子和 UI 七部分。Application 按顺序处理事件、输入、仿真、粒子、场景、UI 和交换缓冲。Renderer 只接收 `const SimulationController&`，从接口层防止渲染代码修改业务状态。逻辑测试只链接 `mine_simulation` 静态库，不需要显卡或窗口。

详细模块和流程图见 `ARCHITECTURE.md`。

## 3. 场景与程序化建模

基础 Mesh 包含立方体、倒角箱体、圆柱体、低多边形不规则岩块、位移网格、梯形盾板和实体螺旋叶片，通过非均匀缩放、旋转、材质和组合形成：

- 真实改变轮廓与法线的岩石底板、顶板、巷帮和煤壁；
- 六组灯具、通风管、警示牌；
- 液压支架的底座、双立柱、顶梁和掩护梁；
- 采煤机机身、左右摇臂、左右滚筒与截齿；
- 输送机槽体、侧轨、机头机尾和移动刮板。

这种方式没有外部模型缺失风险，能在依赖和着色器可用时保持核心场景运行。

## 4. 现代 OpenGL 流水线

每个 Vertex 包含 position、normal、UV。Mesh 构造时创建 VAO、VBO、EBO；Renderer 重复调用同一 Mesh，用不同 Model 矩阵绘制。顶点着色器将位置依次变换到世界、观察、裁剪空间；法线使用逆转置矩阵处理非均匀缩放。

场景片元着色器在线性空间计算环境、漫反射、Blinn-Phong 镜面、点光源衰减、相机锥形头灯和指数平方雾，并生成煤岩、细碎掉漆、金属拉丝与滚筒加工纹。透明煤尘关闭深度写入但保留深度测试。

场景先写入 4× 多重采样 `RGBA16F` 帧缓冲，再 resolve 到单采样 HDR 纹理。后处理依次完成半分辨率亮部提取/高斯模糊、由深度重建的半分辨率 SSAO 与深度感知模糊、ACES 色调映射、曝光、暗角、抖动和 FXAA，最后才绘制 ImGui，因此界面不受 Bloom 和色调映射影响。所有 FBO 会按 framebuffer 像素尺寸重建，并在 GLFW 上下文销毁前释放。

## 5. MVP 与相机

世界坐标规定 X 沿工作面、Y 向上、Z 从煤壁向巷道。Projection 使用透视投影并根据每帧 framebuffer 宽高比更新。自由相机通过 yaw/pitch 生成 forward/right；WASD/QE 位移乘 deltaTime，Shift 只改变速度系数。

固定视角覆盖全景、采煤机、支架、输送机、入口和顶视。顶视位于顶板上方，Renderer 省略顶板形成教学剖面。屏幕拾取把鼠标坐标转换到 NDC，乘逆 PV 得到世界射线，再求设备 AABB 最近交点。

## 6. 设备动画

采煤机速度采用渐近目标，端点钳制后换向。左右滚筒用同一角度相反方向旋转，截齿围绕滚筒圆周重新定位。负载是位置的连续函数，温度按负载缓慢追踪，消除随机抖动。

每台支架拥有独立 Stage/Timer/Pressure。采煤机越过支架后才触发 Waiting，各支架还带轻微不同延迟，随后独立完成降架、移架、升架。动作阶段映射到顶梁高度和 Z 位移。

输送机速度先平滑上升，达到阈值后才解除采煤机联锁。刮板位置取 chainPhase；煤块先抛落到槽面，再以输送机速度沿 X 方向运走。煤块和煤尘均有数量和生命周期上限。

## 7. 状态机与故障

11 个状态覆盖 Stopped、Initializing、Ready、StartingConveyor、双向 Cutting、EndTransition、Paused、Warning、Fault、EmergencyStopped。`canTransition` 明确允许边，`transitionTo` 集中记录前状态、进入时间、原因和事件。

采煤机过热让设备进入 Fault、温度至少 96℃且运动停止；输送机堵塞让链速归零并联锁采煤机；支架低压只影响指定支架并触发 Warning；照明故障关闭工作灯；急停立即停止运动并锁存。清故障后系统回到安全 Stopped，而不是自动恢复运动。

## 8. UI 与交互

ImGui 提供控制站、设备列表/遥测、故障演示、渲染/相机、事件日志和帮助。事件日志可筛选 Info/Warning/Error/Safety、清空和自动滚动。主菜单可恢复默认未展开的日志窗口。UI 捕获键鼠时自由相机和场景拾取不处理同一输入。

## 9. 重构设计

项目从空仓库开始，但开发过程持续以可测试模块替代典型 OpenGL 原型：资源采用 RAII；业务与绘制分离；参数集中在 Config；支架使用独立对象；GLAD 与依赖版本锁定；资源路径兼容中文；程序提供内部截图以获得真实视觉证据。具体问题—后果—修改—收益表见 `REFACTORING.md`。

## 10. LLM 生成实验

GPT-5.6 Sol 接收一份完整任务提示词后直接生成项目。第一次完整配置暴露 GLAD CMake 函数导入和 Python 模块两项错误；第一次运行暴露中文路径；第一次截图暴露相机在岩壁外；第二次截图暴露通风管和 UI 遮挡。模型根据每次真实证据修复，而非把初次生成当作完成。

本实验没有模型对照组，不报告虚构的模型优劣或性能提升。详细评估见 `LLM_EVALUATION.md`。

## 11. 测试与性能观察

自动测试覆盖 Transform、状态转换、换向、暂停、重置、急停、支架阶段、堵塞清除和配置边界。Debug 真实构建并通过 CTest；Release 在最终验收执行。图形冒烟模式创建 NVIDIA OpenGL 3.3 上下文，自动进入割煤并在煤块出现后保存 framebuffer。

当前增强画面在自动割煤截图中约 2000 Draw Calls，主要来自 30 台多部件支架、滚筒截齿和逐件刮板；1500×900、完整 HDR/SSAO/Bloom/FXAA 下，RTX 4060 Laptop 六个 Release 固定机位本轮实测约 163～167 FPS。该数值只记录本机当次结果，实际 FPS 取决于窗口、VSync 和 GPU。

## 12. 限制与后续工作

当前没有 GPU Instancing、直接光源 Shadow Mapping、图片纹理、Assimp 模型、配置保存和性能曲线；设备比例为教学造型而非厂家 CAD。透明粒子未按深度排序，AABB 是旋转部件的保守近似。后续应优先做支架/刮板实例化和灯光阴影贴图，然后增加纹理资源缓存与配置文件，而不是扩大未经验证的玩法。

## 13. 总结

项目完成了从现代 OpenGL 基础资源、程序化场景到设备联动、安全状态机、UI、测试和文档的完整闭环。最重要的工程结论是：LLM 能快速生成复杂图形系统骨架，但必须通过真实编译、运行和视觉检查才能发现依赖、路径与构图问题；安全行为还必须以确定性测试验证，不能依靠画面或文字标签。
